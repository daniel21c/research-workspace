# 서울 시설데이터 패키지 2020 · 2025 (facility-v1.3)

서울 33종 시설의 두 시점(2019-12-31, 2024-12-31) 위치 자료와, 그것을 만든 원본·코드·검증 문서를 한 폴더에 모은 패키지다. **현재 시설 배포본은 v1.3이다. 다른 연구 코드는 이 패키지의 `데이터/`만 참조한다.**

06의 기존 access-engine-v3.1 결과는 v1.2 입력으로 계산되었다. v1.3 시설을 반영한 결과가 아니며, 06 담당자가 연결표·입력 버전 검사·출처 지문·결과를 갱신해야 한다. 이번 작업에서는 06을 수정하거나 재계산하지 않았다.

## 2. 문서 읽는 순서 (`문서/`)
1. **`출처_전처리_안내.md`** — 33종 각각의 출처(기관·자료·데이터셋 ID·기준일·등급), 원본 위치, 전처리 코드 경로, 범위 규칙, 좌표 방식. 공통 규칙(시점·역산·지오코딩·공간 결합)
2. `분석용파일_설명.md` — 분석용 파일의 열과 국가기준 분류(마을단위·지역거점·보조), 사용 예
3. `무결성_검증.md` — 코드 전수조사·결과 검증에서 고친 것과 남은 한계, 지오코딩 표본 시험
4. `신뢰도_판정표.md`, `신뢰도_작업지침.md` — 신뢰도 '상' 판정 기준(공식 통계 ±5%, 좌표 ≥95%, 85% 미만 구 없음)과 시설별 판정
5. `구축사양_SPEC.md`, `원빌드_결과표.md`, `채택_이력.md`, `작업기록.md` — 구축 사양과 경과(이력 문서)
6. `참고문헌/` — 제2차 국가도시재생기본방침(별표2 기초생활인프라)

이력 문서(5번)는 정리 전 폴더 이름으로 적혀 있다. 대응: `시설_2020_2025_v1/` → `구축코드/`, `10_신뢰도_상/<시설>` → `데이터/시설별/<시설>`, `10_신뢰도_상/_중/` → `데이터/민감도용/`, `20_분석용/` → `데이터/`, `SGIS_인구경계_2019_2024/`는 패키지 바로 아래.

## 4. 사용 예
```python
import pandas as pd
f = pd.read_parquet(r'.../시설데이터 구축/시설데이터_패키지/데이터/서울시설_2020_2025_분석용.parquet')
f = f[f['분석가능']]                       # 서울 안 + 검증된 좌표
t2020, t2025 = f[f.year == 2020], f[f.year == 2025]
```
- `facility_id`는 두 시점 같은 시설이면 같다(시설·facility_id·year로 고유, 예외: 버스정류장 2020 BUS_15143 원천 중복 1건).
- 행정동(`adm_dong_cd`, 426)·집계구(`oa_cd`)·100 m 격자(`grid100_cd`)는 두 시점 모두 SGIS 2025_2Q 경계로 붙였다.

## 5. 다시 만들기 (`구축코드/`)

현재 채택본의 통합·분석용 파일을 **별도 검증 폴더**에 다시 만들어 바이트 해시를 비교한다(API·키 읽기 없음).
```powershell
python 구축코드/13_좌표보완/release_v13.py verify
```
v1.2 입력 스냅샷 + 87행 보완 근거 + 6행 파서 정정 근거에서 v1.3을 다시 생성하려면 `python 구축코드/13_좌표보완/release_v13.py stage`를 사용한다. `staging/`에만 생성하며 공식 배포본을 덮어쓰지 않는다. 필요한 환경: Python 3.12, pandas 3.0.2, pyarrow 23.0.1, geopandas, pyproj. 과거 보정 스크립트는 당시 구축 이력이며 현재 배포본 위에 무조건 다시 실행하지 않는다.

원자료·기존 캐시·SGIS·원천 산출물과 `보완후보_20260929/입력/` 스냅샷은 재현에 필요하므로 보존했다. 기존 87행 후보의 생성·검증 기록은 당시 v1.2가 활성 입력이었던 증거이며, 승격 후 재현은 위 v1.3 스크립트를 쓴다. 공원 PBF는 본33종 입력이 아닌 06 네트워크의 별도 원자료 의존성이고, 이번 범위에서 재현하지 않았다.
