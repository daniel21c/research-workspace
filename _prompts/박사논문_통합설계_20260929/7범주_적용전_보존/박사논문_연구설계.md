## 1. 논문이 답해야 할 질문

> "생활권 계획 왜 해? 접근성이 문제면 격자로 15분을 계산해서 시설을 배치하면 되는데, 왜 생활권이라는 중간 계획단위가 필요한가?" (09:06~10:09)

- 교수님은 이 질문을 "마지막 한 조각이면서 가장 큰 조각"이라고 했다(09:06). 앞의 연구들이 잘 풀려도 이 질문에 답하지 못하면 박사논문이 되지 않는다(17:00~17:18).
- 반드시 넘어야 할 반론
  1. 접근성 취약지역은 격자만으로도 찾을 수 있다.
  2. 시설 배치는 생활권 없이 격자·행정동 단위로도 할 수 있다.
  3. 이동데이터로 권역을 만들었다고 그것이 곧 계획단위가 되어야 하는 것은 아니다.
  4. 접근성은 원래 경계와 무관한 지표인데, 거기에 다시 경계를 씌우는 이유가 무엇인가(13:40).
- 생활권은 15분 도시와 다르다. 15분 도시는 "내 집 기준"이고, 생활권은 행정적 사고로 만든 권역이다(06:56~07:02, 10:37~10:45).
- 서울은 전 세계 도시 중 하나의 사례일 뿐이다(29:25~29:29). 서울시 제도 설명에 비중을 두지 않는다.

## 2. 논리 흐름과 4장 순서

교수님이 제시한 흐름(30:23): **왜 필요한가 → 어떻게 짜는가 → 짰으면 끝인가, 불일치는 왜 생기는가 → 계속 변하므로 시점별로 어떻게 진단·재정비하는가**

- 필요성을 앞에 두는 편이 낫다(20:57~21:16). "해봤더니 이런 의미가 있다 → 그러면 필요하다 → 어떻게 만드나"로 간다.
- 논문상 순서는 JTG → AG → 시계열(22:43~23:22). AG와 KPA의 순서가 조금 애매하지만 고민할 필요 없이 이대로 간다(26:21~26:23).

## 3. 장 구성 (5장)

- 1장 서론: 생활권·중간계획단위가 세계적으로 도입되는 흐름, 그 유효성·실효성 질문, 근거기반 정책(EBPM), 과학적 데이터의 필요성, 국가 R&D·빅데이터 기반 도시계획 기술(49:01~49:32). 중간발표에 반드시 나와야 한다(48:24).
- 2장 선행연구: 절마다 4장의 절과 1:1로 대응한다(49:46~50:22). 여기에 해외 중간계획단위의 목적·역할 검토를 포함한다(21:57).
- 3장 분석의 틀: 전체 프레임워크, 자료, 네 연구의 연계.
- 4장 분석결과: 4.1~4.4. 분량이 많으면 4장을 두 개 장으로 나눌 수 있다(03:37, 47:26).
- 5장 결론: 생활권의 계획적 존재 이유와 설정 조건, 동적 진단·재정비(도시기본계획 20년·관리계획 10년처럼 생활권도 주기적 재정비, 30:23~31:02), 기여와 한계.
- 5장 구성이 기본이다(03:05~03:37).
- 폴더 추가 (2026-09-24 사용자 결정, 접근성 대화): 4.1·4.3·4.4가 공유하는 시설 접근성 계산(Coverage·MAI·도달시간, 2026-09-25 2SFCA 추가)은 `06_접근성분석/접근성분석_패키지/`(공통 접근성 엔진, 패키지 README 참조)에서 한다. 지표 정의는 `06_접근성분석/접근성분석_패키지/문서/지표정의_확정.md`, 자료 가공은 `06_접근성분석/접근성분석_패키지/문서/자료가공설계.md`. 각 연구 폴더는 이 엔진의 산출물을 읽기만 한다.

## 4. 연구별 설계 기준

### 4.1 연구1 — 생활권 필요성 (폴더 `01_생활권_필요성`)

**질문**: 격자 기반 계획과 생활권 기반 계획은 무엇이 다르고, 무엇이 이익이고 무엇이 손해인가(14:36).

**교수님 지침**
- 비교 단위 4개: 격자, 행정동, 생활권, 자치구(16:35~16:41).
- 실제 서울 자료가 아니어도 된다. 가상공간 또는 한 개 구에 시설과 인구를 무작위로 뿌리고, 생활권 기준 배치와 격자 기준 배치를 비교하는 이론적 모의실험이면 된다(14:36~15:33). 논문으로 따로 낼 필요는 없다(14:36).
- 검토 축 두 가지(요약본 4절)
  1. **효율 vs 형평**: 도시 전체 Coverage·MAI를 최대화하면 수학적으로 늘 인구가 많은 곳부터 높인다. 생활권별로 최소 수준을 보장하면 인구가 적은 취약지도 끌어올린다. "비슷하게 움직이는 권역끼리는 동등하게 대우하자"(11:32~12:36). 의도적 투자를 특혜 시비 없이 정당하게 골라내는 기준이 된다(12:36).
  2. **행정 효율**: 공공은 격자 단위로 의사집행할 수 없다(15:44~15:52). 행정동은 너무 작고 구는 너무 크다. 시설 추가·폐지는 협의가 필요하고, 이해관계자를 줄이면 협의가 된다(45:56~46:21). 이 축은 직접 분석보다 선행연구·제도 논의(일본 사례 등)로 끌고 간다(46:21~46:52).
- 교수님은 행정 효율 쪽 효과가 더 클 것으로 보았지만, 무엇으로 측정할지는 정해지지 않았다(20:27~20:34).
- 결론은 "생활권이 필요하다"로 미리 고정하지 않는다. 이익과 손해를 모두 보고한다.

**설계 대화에서 정할 것**: 모의실험 공간(가상 vs 특정 구), 인구·시설 생성 방식, 배치 규칙(목적함수·예산), 지표(효율·취약지·형평), 행정 효율의 측정 또는 논증 방식, 비교의 공정성(같은 인구·후보지·예산).

**참고(샘플 단계 교훈)**: 이전 `simulate_spatial_units_equity.py`의 표(효율 95.8, Gini 0.218 등)는 코드에 직접 적은 값이었다. 인용 금지.

### 4.2 연구2 — 생활권 구획과 점검, JTG (폴더 `02_생활권_구획_JTG`)

**질문**: 생활권이 필요하다면 어떻게 짜야 하나(30:23). 지금은 아무도 모르는 블랙박스다.

**교수님 지침**
- 이동 빅데이터와 알고리즘으로 구획하면, 맥락을 고려해 만든 공식 생활권과 거의 같게 나온다. 이것이 "빅데이터에는 맥락이 없다"는 거부감에 대한 답이다(18:37~19:29).
- 구획 결과로 실제 이동을 반영하지 못하는 불일치를 찾아내, 선별·개선하는 진단 도구가 된다(19:29~20:27).
- 합의형성 알고리즘의 무작위성 때문에 값이 달라진 문제가 있다. 게재 당시 코드로 다시 확인한다(32:10~32:28).
- 시간 여유가 있으면 JTG 논문을 한글로 옮겨 둔다(47:26~48:06).

**설계 대화에서 정할 것**: 게재본 방법의 재현 기준(당시 코드·반복 수·선정 규칙), 현재 합의 알고리즘과의 차이 검증 방법, 학위논문 4.2절에서 게재본을 어떻게 요약·확장할지.

**데이터 의존**: 경계 생성 작업(별도 대화)의 결과. 이 대화는 경계 코드를 직접 고치지 않고, 검증 설계와 요구사항만 정리한다.

### 4.3 연구3 — 불일치와 접근성, AG (폴더 `03_불일치_접근성_AG`)

**질문**: 공식 생활권과 이동 경계가 어긋나는 이유는 무엇인가? 접근성인가(23:31~24:00)?

**교수님 지침**
- 종속변수는 내부통행률(IFR)로 간다. 다른 변수를 구할 데이터가 없다(41:04~41:58).
- 핵심 변수는 MAI, Coverage, IFR. "분석 심플하게"(42:36~42:39).
- 시설자료: 직접 구축한 33종(`시설데이터 구축/시설데이터_패키지/데이터/`)의 기능 카테고리 8개를 `06_접근성분석` 공통 엔진으로 계산해 쓴다. 승훈 씨 8종·250m 격자·승훈 OD는 쓰지 않는다 (2026-09-24 사용자 결정, 접근성 대화). **9/21 지침(42:30~42:35)과 다르므로 교수님께 보고한다.**
  - 변경 이력(2026-09-24): ~~시설자료는 승훈 씨의 기존 8종을 그대로 쓴다(42:30~42:35).~~ (녹취 기록은 그대로 유지, 적용만 대체)
- 면적·컴팩트성은 통제변수이지 핵심 해석 지표가 아니다(42:55~43:15).
- 요약본 6.1: MAI가 도달 가능한 대상을 조건부로 계산한 지표임을 명확히 쓴다. 공간모형(Moran's I, SLM/SEM)은 OLS 왜곡 확인·강건성 용도로만 쓴다. (이 두 항목은 9/21 녹취 본문에서는 직접 확인되지 않았다.)
- 9월 중 투고(32:31~33:25).

**설계 대화에서 정할 것**: 분석 단위와 표본, 변수 정의(MAI·Coverage의 정확한 식과 분모), 모형식, 강건성 점검 범위, 투고본과 학위논문 4.3절의 관계.

### 4.4 연구4 — 불일치의 시간 변화 진단, KPA (폴더 `04_불일치_시간변화_KPA`)

**질문**: 불일치가 시간에 따라 어떻게 변하나? 재정비가 필요한 곳을 어떻게 찾나?

**기준 원고 (사용자 결정, 2026-09-23)**
- 연구4는 이미 작성된 시계열 논문이다. 기준은 **접근성 개념이 들어가기 전 판본**인 `D:\Research\999_논문\국토학회_시계열비교\251230_데이터 기반 커뮤니티 분석을 활용한 도시 생활권 경계의 정량적 평가에 관한 연구.docx` (같은 이름 PDF 있음). 제목: 데이터 기반 커뮤니티 분석을 활용한 도시 생활권 정합성의 정량적 평가에 관한 연구 — 서울시 사례를 활용하여.
- 비교 시점은 **2020 vs 2025 두 시점**으로 한다(9/21 요약 6.2 "두 시점 비교 중심으로 단순하게").
- 이후 판본(2026-04 `260421_수정본`·`260424_*`의 접근성 추가본, 2026-09-02 국토계획 투고본 v12의 4시점+소매 접근성)은 4.4의 기준으로 쓰지 않는다. 접근성은 4.3(AG)에서 다룬다.

**교수님 지침**
- 핵심 기여는 진단법이다. 시계열 변화는 IFR만 계산해서는 볼 수 없으므로, 시계열 커뮤니티 불일치를 진단하는 새 방법을 제안했다(24:44~25:26).
- 서울에 적용하니 불일치가 커지는 방향으로 변했다. 진단된 지역은 경계를 다시 짜거나, 그 안의 접근성을 높이는 방향으로 대응한다(25:31~26:21).
- 불일치 격차를 진단하고 선별해서 개선한다는 데서 끝낸다(33:43~33:46).
- 알고리즘을 점검하고 결과를 갈아 끼운다(33:14~33:21, 43:21~43:25).
- 시설자료는 직접 구축하지 말고 어디까지 입수 가능한지만 먼저 정리한다. 두 시점 자료가 다 있으면 접근성 변화도 함께 볼 수 있다(43:30~44:01).
- 9월 중 투고.

## 6. 공통 정의와 데이터 원칙

샘플 단계 검증(2026-09-23)에서 드러난 문제를 반복하지 않기 위한 원칙이다.

1. **지표 정의는 한 곳에서만 정한다.** IFR, Modularity Q, IoU, MAI, Coverage의 식·분모·단위는 해당 연구의 `연구설계.md`에서 정하고, 여러 연구가 같이 쓰는 정의는 이 문서 7절 표로 옮긴다.
   - 예: 샘플 코드에서는 Q가 모듈마다 달랐다(동 내부통행 포함 여부). IoU는 "1:1"이라 적혀 있었지만 다대일이었다.
2. **집계는 원량으로 한다.** 상위 단위 IFR은 하위 단위 비율의 평균이 아니라 분자합/분모합이다.
3. **데이터는 배포본만 쓴다.** 경계·시설 자료는 각 생산 대화가 확정하면 `데이터_배포목록.md`에 경로·버전·해시를 적는다. 연구 대화는 목록에 있는 것만 읽는다.
4. **결과 수치는 코드에서 나와야 한다.** 표·보고서에 숫자를 직접 적지 않는다.
5. **난수는 기록한다.** Leiden 등 무작위 알고리즘은 seed와 반복 수를 남긴다.
6. **본문에 작업 메모를 쓰지 않는다.** PASS/BLOCKED/검증 필요 같은 표현은 논문과 발표에 남기지 않는다(요약본 6.3). 연구자가 모든 계산을 설명할 수 있어야 하고, 다른 도구로 교차검증한다.
