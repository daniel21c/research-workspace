## 2. 구현 규칙

1. **분석 대상 시설**: 해당 시점(`year`) · `분석가능` = True · `role` ≠ control · `cat_A`가 8개 카테고리 중 하나. 격자 번호는 시설 파일의 `grid100_cd`(250m은 `grid250_cd`). 격자 마스터에 없는 격자(서울 경계 밖)의 시설은 제외: 100m 2020·2025 각 40행, 묶음 B 각 8행.
2. **C_g 비트마스크**: 카테고리 순서 = `a00_config.CAT_A` 키 순서(교육, 보육·복지, 의료, 문화, 체육, 행정·안전, 소매, 생활서비스 → bit 0..7). `np.bitwise_or.at`으로 만들어 같은 격자에 같은 카테고리가 여럿 있어도 비트는 하나. |C_g| = popcount. 시설 격자 수 2020 25,145 / 2025 25,054, |C_g| 최대 7 (a02 기록의 25,161 / 25,067과의 차이는 격자 마스터 밖 시설 격자 16·13개).
3. **출발**: 해당 시점 인구 > 0 격자(100m 2020 30,751, 2025 30,785; 250m 7,005 / 7,034). 소요시간표 출발(pop_or_biz)에 인구>0 격자가 모두 들어 있음을 확인(빠진 격자 0). 인구 0·사업체만 있는 출발은 지표에서 뺀다.
4. **경계 조건 b** ∈ {none, dong424, lz116, ld, ku}: 도착 격자의 단위(격자 중심점 규칙, 격자 마스터 열) = 출발 격자의 단위. `ld`는 2020 → `ld2020`, 2025 → `ld2025`.
5. **속도 민감도**: 표의 t(4.0 km/h 기준) × 4.0/speed 로 환산한 뒤 T와 비교. 3.6 km/h면 표 상한 1,800초가 2,000초가 되므로 T=900은 안전(엔진은 T > 1,800×4.0/speed이면 거부).
6. **격자 지표**(출발 o × b × c): r = 1[T 안의 c 격자 존재], m = 그 격자들의 |C_g| 최댓값(r=0이면 결측), t_min = 30분 표 안의 최근접 시간(b 조건 적용, 없으면 결측), `--union`이면 U = T 안 도달 격자 C_g 합집합의 카테고리 수.
7. **단위 집계**(u ∈ dong424, lz116, ld, ku, seoul): COV = Σp·r/Σp, MAI = Σp·r·m/Σp·r, PWATT = Σp·r·t/Σp·r (r=1 ⇔ t≤T, 같은 b). 종합: COV는 K개 단순평균, MAI·PWATT·UNI는 값 있는 카테고리 단순평균(`n_cat_mai`에 개수). 모두 격자 값에서 바로 분자합/분모합 — 동 값의 평균을 쓰지 않는다.
8. **묶음 B**: b = none, 하위유형별 τ(유치원 10분, 초등학교 15분, 어린이집 5분, 의원·약국 10분, 체육 4종 10분, 일상소매 10분). 카테고리 충족 = 하위유형 중 하나라도 τ 안(OR). 종합 = 5개 단순평균. 하위유형별 충족률도 함께 저장.
9. **A4**: 시설 파일 `cat_A4`(교육·복지 / 의료 / 체육·문화 / 소매·서비스·행정)로 C_g를 다시 만든다(MAI 범위 1~4).
10. **일상소매 제외**: `시설` = 일상소매 행 제거(2020 26,494행, 2025 29,063행) 뒤 A 8개로 계산 — 소매 카테고리는 식료품소매+대규모점포만 남음.

## 5. 범위 밖·못 한 것

- **체육 "규칙 없음" 민감도**: 분석용 파일에 취소·말소 체육시설업 행이 없어(규칙 C가 이미 적용된 판) 계산 불가. 원본 빌드에서 규칙 없는 판을 새로 만들어야 하는데 `시설데이터 구축/`은 읽기 전용이라 이번에는 하지 않았다.
- **면적비 격자 배정**(연구1 전용 민감도): 이번 범위 밖. 필요하면 격자×동 교차 면적표를 만든 뒤 엔진의 단위 번호를 가중치로 바꾸는 확장이 필요.
- 도달시간 t_min은 30분(표 저장 상한, 속도 환산 후) 안의 값만 있다. 30분 밖은 결측이며 0이나 30으로 채우지 않았다.

## 6. 한계

1. **OSM 2025 보행망 +31.6%**(12,562 km → 16,533 km)는 대부분 footway·service·path 매핑 증가다. 2020→2025 변화에는 실제 시설·인구 변화와 네트워크 표현 변화가 섞인다. 실제로 15분 도달 셀 중위가 162 → 159로 약간 줄었고 서울 PWATT가 3.90 → 4.03분으로 늘었다. → 2026-09-25 네트워크 고정 민감도(`sens_net2025`, 7절)로 분리했다: PWATT 증가의 대부분이 네트워크 몫이고, COV 증가는 시설·인구 몫이다(네트워크 몫은 오히려 음).
2. **일상소매 2020**은 정보공개청구 원본이 아닌 재작성본(수준 약 −10% 편향). 원본이 오면 `facility_2020_2025_units.parquet` 교체 후 `run_engine.bat` 재실행. 일상소매 제외 민감도에서 서울 종합 COV 변화는 −0.0003 이내, MAI는 −0.17~−0.18(소매 격자 감소로 동시입지 수 감소).
3. **공공체육(신뢰도 중)**: 체육 카테고리는 체육시설업(신고 업종)만. 공공체육시설 보강은 선택 과제.
4. **250m 격자**는 셀이 커서 |C_g|가 커지고(최대 8) MAI가 약 +1.5 높다. 수준 비교가 아니라 순위·차이 비교용.
5. 스냅 거리 200m 초과 출발 격자(2020 100m 51개, 2025 4개)는 그대로 포함. 격자 중심→노드 스냅 거리는 소요시간에 더하지 않았다(`네트워크_소요시간표_구축기록.md`).
6. MAI 필수 문구: MAI는 경계 안에서 해당 카테고리 시설에 도달한 인구만을 대상으로 한 조건부·상한 지표이며, 실제 통행사슬을 재현하지 않는다. 도달하지 못한 인구의 값은 0이 아니라 정의되지 않으며, 그 사정은 Coverage가 보여 준다.

## 7. 네트워크 고정 민감도 `sens_net2025` (2026-09-25 추가, 사용자 PC Windows에서 실행)

- 목적: 2020→2025 변화 가운데 보행망 자료 변화(OSM 매핑 +31.6%) 몫을 분리. 2020 시설(2019-12-31)·인구(2019)·Leiden 2020 경계를 그대로 두고 소요시간표만 2025-01 보행망(`ttm100_2025`)으로 바꿔 main 2020과 비교한다.
- 엔진 옵션: `a06_engine.py --net-year`(기본 = `--year`), `--out-root`(재현 점검용 출력 위치). 기본 실행의 결과·run_meta 키는 바뀌지 않는다 — 이 PC에서 main 2020·2025를 다시 돌려 `unit_access` CSV가 manifest 해시와 바이트까지 같고 `grid_access` parquet 내용이 같음을 확인. 이를 위해 CSV·JSON·요약 md 줄바꿈을 `\n`으로 고정(Windows 기본 CRLF 방지; 값은 그대로).
- **보충 소요시간표**: `ttm100_2025`의 출발 셀은 2024 인구·사업체 기준이라 2019 인구>0 셀 중 493셀(인구 63,679명)이 출발로 없다. 엔진은 표에 없는 출발을 미도달(r=0)로 채우므로 그대로 쓰면 틀린다. `02_scripts/a05c_ttm_supplement.py`가 같은 코드 경로(a05의 스냅 파일·run_chunk·dijkstra)로 이 셀들만 계산해 `01_data/ttm/ttm100_2025_for2020/`(25청크, 276,771쌍)에 따로 둔다. 확정본 `ttm100_2025/`는 건드리지 않았다. 재현성 점검: 확정본에 있는 출발 40개를 다시 계산해 저장된 26,709쌍과 완전 일치. 요약 `01_data/ttm/ttm100_2025_for2020_summary.json`.
- 엔진은 `--net-year`가 `--year`와 다르면 확정표 + 보충표를 합쳐 읽고, 그래도 빠진 출발이 있으면 중단한다. 실행 결과 출발 30,751셀(main 2020과 같음) 누락 0, 소요시간표 22,902,253행, 불변조건 모두 통과.

- **2SFCA 구현** (`a06_engine.py`: `build_supply`, `sfca_access`, `sfca_outputs`; 정의 `지표정의_확정.md` 3.4)
  1. 공급 행렬 S(격자 × 항목): 항목 = 기능 카테고리 8개 + 시설 28종(36개). 값 = 격자별 분석가능 시설 **개수**(MAI의 비트마스크와 달리 같은 격자 중복도 하나씩). 격자 마스터 밖 시설(100 m 각 40행)은 제외 — Coverage·MAI와 같은 규칙. 일상소매 제외 세트에서는 일상소매 항목이 빠진다.
  2. 구별 분할을 읽는 동안 15분 안(속도 환산 뒤) 쌍(o, g)을 모두 모은다(인구>0 출발만). 집수역이 구 경계를 넘으므로 2SFCA는 서울 전체 실행에서만 계산하고 `--ku` 시험 실행에서는 건너뛴다.
  3. 경계 조건 b마다: D_b(g) = Σ 같은 단위 쌍의 p_o, R = S/D(D = 0이면 할당 안 됨), A_b(o,k) = Σ 같은 단위 쌍의 R(g,k).
  4. 단위 집계: Σ p·A / Σ p × 10,000(동·공식·Leiden·구·서울), 15분 안 시설 없는 인구 비율(pop_share_A0), 단위 안 시설 수, 할당 안 된 시설 수, b = none 행의 경계 개방비 open_ratio = SFCA(없음)/SFCA(그 단위 자신의 경계).
  5. 불변조건(run_meta checks): A ≥ 0, 서울 전체 공급 보존 Σ p·A = Σ 할당된 S(상대오차 < 1e-9), 단위 자신의 경계에서 단위마다 공급 보존(절대오차 < 1e-6).
  6. 산출: `sfca_unit_{연도}_{격자}.csv`(묶음 A 모든 세트), `grid_sfca_{연도}_100.parquet`(본 분석만, `--save-sfca-grid`).
