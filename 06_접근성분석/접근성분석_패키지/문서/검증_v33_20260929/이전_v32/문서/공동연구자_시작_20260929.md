## 재현

실제 검증 환경은 `데이터/release_provenance.json`에 기록했다(Python 3.12). 설치는 사용자가 별도 환경에서 `코드/requirements.txt`를 참고한다. 결과를 보존하려면 먼저 저장소 밖의 새 출력 폴더를 지정한다.

```powershell
python -B -X utf8 코드/a06_engine.py --year 2020 --grid 100 --tag main --save-sfca-grid --out-root <새출력폴더>
python -B -X utf8 코드/a06_engine.py --year 2020 --grid 100 --tag xb_main --ld-other --out-root <새출력폴더>
python -B -X utf8 코드/a06_engine.py --year 2020 --grid 100 --tag xb_net2025 --ld-other --net-year 2025 --out-root <새출력폴더>
python -B -X utf8 코드/a06d_temporal_sensitivity.py --out <새민감도폴더>
```

2025 실행은 year를 2025로 바꾼다. 엔진의 전체 설정은 `run_engine.bat`에 있다. 이 배치는 정본 결과를 갱신하므로 공유받은 사본에서만 실행한다. SGIS·시설 전처리·TTM을 다시 만들 때는 출처 연결표의 원천 기록과 해시부터 확인한다. OSM PBF 본체는 저장소에 없으므로 원래 URL과 해시로 별도 확보하여 a04의 `--pbf`로 지정해야 한다. 자동 재다운로드/재수집은 이번 작업에 포함하지 않았다.

## xb와 시점 차분의 추가 민감도

`xb_main`은 2020·2025 시설/인구/보행망에 해당 연도 LD(`ld`)와 상대 연도 LD(`ld_other`)를 함께 배정한다. `xb_net2025`는 2020 시설·인구 + 2025 보행망 + LD2020/LD2025이다. `ld_other`는 경계 조건과 집계 단위 모두에 추가되며 xb에서는 2SFCA를 계산하지 않는다. 본 분석 경로·정의는 유지하고 값은 시설 v1.3으로 갱신했다.

`temporal_dmai_common4`는 두 시점×두 경계 네 조건 모두에서 유효한 범주 집합 K*를 고정하여 평균[(MAI_LD1−MAI_LZ1)−(MAI_LD0−MAI_LZ0)]을 계산한다. 공통범주 수와 목록도 반환하며 K*=0은 NaN이다. `데이터/결과/temporal_common4/`에 본 설정, 망2025 고정, LD2020/2025와 망2025 동시 고정, 스냅 포함 이동경계의 다섯 표를 제공한다. 모두 동424 전체이며 특정 논문의 분석표본에 자동 결합하지 않았다. 기존 연도별 두 경계 ΔMAI가 기본이고 공통4는 추가 민감도다. LD 고정×스냅 포함의 결합 민감도는 미실행이다.

## 논문에 쓸 때의 제한

COV의 분모는 전체인구, MAI와 PWATT의 분모는 해당 범주에 도달한 인구이다. 상위 공간 단위는 격자 분자·분모를 각각 합산한다. 미도달 MAI/PWATT를 0으로 채우지 않는다. 2SFCA 공급은 시설 개수이며 수용인원·면적·서비스 품질을 반영하지 않는다. 경계 제한은 출발·도착 격자의 소속이 같다는 조건이며 이동 경로 전체가 경계 안에 머문다는 조건이 아니다. 서울 밖 시설은 없고 스냅/OSM 수록 변화/소매 재구성/250m 면적 배정에 불확실성이 있다. 수준 순위가 안정적이어도 작은 시점 변화의 부호가 안정적이라는 뜻은 아니다. 10분·250m ΔMAI 민감도 및 공통4 결과를 함께 제시하고, 교차경계 진단을 공식 생활권 대체나 인과 효과로 기술하지 않는다.
