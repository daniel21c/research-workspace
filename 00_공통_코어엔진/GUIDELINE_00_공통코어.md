## 2. 4대 핵심 알고리즘 운영 원칙

### [원칙 1] Leiden 커뮤니티 구획 및 합의(Consensus) 무결성 원칙
* **라벨 스위칭 방어:** 단순 단발성 Leiden 실행 결과 채택을 엄격히 금지한다.
* **Co-association Matrix 기반 합의:**
  * 해상도 탐색 및 최종 구획 시, 각 해상도마다 $K \ge 200$회(최대 1,000회) Leiden을 반복 실행하여 동시 소속 행렬 $C_{ij}$를 누적한다.
  * $C_{ij} \ge \tau (0.5)$인 쌍으로 합의 그래프를 구축하고 연결 요소(Connected Components)를 최종 커뮤니티로 확정한다.
  * 상대적 소속 확률만 누적하므로 독립 실행 간 일치도 $ARI = 1.0000$을 상시 유지해야 한다.
* **탐색 단계별 합의 필수:** 1회 실행 결과와 합의 결과의 커뮤니티 수가 다를 수 있으므로, 해상도 전수 스캔(0.01~2.50) 시 반드시 각 해상도에서 합의 과정을 거친 후 목표 커뮤니티 수(116개) 일치 여부를 판별한다.
* **고속화:** 행렬 누적 연산은 무결성이 검증된 NumPy 브로드캐스팅(`co_assoc_matrix += (mem[:, None] == mem[None, :])`)을 사용한다.

### [원칙 2] IFR (Internal Flow Ratio) 다위계 산출 원칙
* **방향성(Directed) 원본 유지:** 구획용 대칭화 네트워크와 달리, IFR 계산 시에는 실제 출발지($o$)와 도착지($d$)의 방향성 통행량 $f_{od}$를 100% 보존한다.
* **단순 산술평균(`mean()`) 엄격 금지:**
  * 단위별 크기와 통행량 비중이 상이하므로, 상위 위계 집계 시 절대로 하위 단위의 IFR을 단순 평균내지 않는다.
  * 반드시 **"하위 단위 내부완결 통행량의 합(분자합) / 총 출발 통행량의 합(분모합)"**으로 집계한다:
    $$\text{IFR}_{\text{집계단위}} = \frac{\sum \text{Internal Flow}}{\sum \text{Total Outflow}}$$
* **다위계 3단계 일치성 보장:**
  1. **동별 (423개):** 동 $d$ 출발 $\to$ 소속 생활권 $c(d)$ 내부 도착 통행합 / 동 $d$ 총 출발 통행합
  2. **생활권별 (116개):** 생활권 $c$ 내부 완결 통행합 / 생활권 $c$ 총 출발 통행합
  3. **구별 (25개):** 구 $g$ 내 모든 생활권 내부완결 통행합 / 구 $g$ 내 모든 생활권 총 출발 통행합
  4. **서울 전체:** 전체 내부완결 통행합 / 전체 총 출발 통행합  
     → 수학적으로 **서울 전체 IFR = 구별 가중합 IFR = 생활권 가중평균 IFR**이 완전 일치해야 한다.

### [원칙 3] IoU (Intersection over Union) 공간 정합성 산출 원칙
* **평면직각좌표계:** 면적 왜곡 방지를 위해 반드시 `EPSG:5179` (단위: $m^2$) 투영좌표계에서 계산한다.
* **1:1 최대 면적 매칭:** 자치구 경계 내에서 공식 생활권과 이동 커뮤니티 간 $\frac{\text{Area}(A \cap B)}{\text{Area}(A \cup B)}$가 최대인 단 하나의 파트너를 1:1로 매칭한다.
* **면적합 기반 집계:**
  * $\text{Gu\_IoU} = \frac{\sum_{\text{Gu}} \text{Intersection Area}}{\sum_{\text{Gu}} \text{Union Area}} \times 100 (\%)$
  * $\text{City\_IoU} = \frac{\sum_{\text{City}} \text{Intersection Area}}{\sum_{\text{City}} \text{Union Area}} \times 100 (\%)$

### [원칙 4] Modularity Q 산출 원칙
* 서울시 전체 행정동 간 무방향 대칭화 통행량($w_{ij} + w_{ji}$)을 엣지 가중치로 하는 단일 통합 그래프 $G$를 구성한다.
* Newman & Girvan 수식을 따르는 `python-louvain` 표준 함수를 사용하여 공식 생활권 대비 레이든 커뮤니티의 모듈러리티 우위를 비교·검증한다.

## 3. 교수님 지도 기반 AI 활용 및 연구 윤리 5대 불문율

> **"AI한테 그냥 펄딱 빠져갖고 그렇게 쓰면 안 돼요... 코딩 맡기니까 뭘 하고 있는지 모르겠지. 심사 때 그대로 내면 난리 나요." (2026.09.21 지도)**

1. **내부 개발 메모 및 방어적 주석 본문 기재 절대 금지:**
   * `PASS`, `BLOCKED`, `검증 필요`, `확인 요망` 등 AI가 책임을 회피하기 위해 다는 방어적 주석을 코드 파일, 보고서, 논문 본문에 절대 남기지 않는다.
2. **연구자 코드 완전 장악 원칙:**
   * AI가 작성한 코드는 연구자 본인이 분자·분모 및 실행 흐름을 완전히 이해하고 설명할 수 있는 코드만 남긴다. 이해되지 않는 블랙박스 코드는 배제한다.
3. **통계 수치 춤춤(Hallucination) 방지 및 독립 교차 검증:**
   * 코드를 수정한 후에는 반드시 독립된 검증 스크립트로 오차 0 여부를 교차 확인한 뒤 산출물을 확정한다.
4. **시계열 분석의 담백한 마무리 원칙:**
   * 2020년 vs 2025년 비교는 "공식 생활권과 실제 통행 경계 간의 불일치 및 갭 진단"으로 명확히 마무리한다. 없는 데이터를 무리하게 확장하여 모델을 늘리지 않는다 ("거기서 끝내").
5. **학위논문 로드맵 정합성:**
   * 모든 산출물은 교수님이 제시하신 핵심 질문인 **"격자 기반 계획 vs 생활권 기반 계획의 차이(효율성 vs 형평성)"**를 입증하는 논리적 근거로 연계되도록 정렬한다.
