# 연구 요구사항 복원과 대화 조사 범위

작성 기준: 2026-09-23. 이번 문서는 **조사·설계 결과**다. 연구 코드 수정, 원자료 변경, Leiden 재구획, OLS·시설접근성·시계열 분석의 새 실행은 하지 않았다. 실행 설계는 [RESEARCH_REPAIR_DESIGN_20260923.md](RESEARCH_REPAIR_DESIGN_20260923.md)에 있다.

## 1. 복원된 연구 의도

사용자가 원한 것은 여섯 폴더를 만들고 기존 숫자를 옮기는 일이 아니라, **생활권이라는 중간 계획단위가 왜 필요한지 검증하고, 기존 JTG 방법·AG 접근성 관계·KPA 시간 변화 진단을 설명 가능한 공통 계산으로 연결하는 것**이다. 현재 가장 큰 문제는 계산 완료와 연구 질문 해결을 혼동한 점이다.

- **01**은 공통 예산으로 격자·동·생활권·구의 효율성과 형평성을 비교하는 새 연구다. 생활권의 효율 95.8%, Gini .218, 최소보장 94.8%는 코드 상수이며 실험 결과가 아니다. 예시로 보존하되 실증으로 인용하지 않는다.
- **00**의 가중 IFR 집계는 기존 감사에서 재현되었다. 그러나 IoU의 일대일 명칭, 원본 공식 경계와 동 재구성 경계의 구분, 새 Leiden 실행의 스키마·실패 처리·난수 기록이 미완성이다.
- **03 AG**의 사용자가 명시한 방향은 접근성 MAI·Coverage를 설명변수로 두고 IFR을 설명하는 것이다. 가이드의 역방향 식과 맞추어야 한다. 기존 6종·N=25 회귀, 과거 8종 구상, 새 4종 접근성 결과는 서로 다른 입력 계약이다.
- **04 KPA**는 시설접근성을 본 분석에서 제외하고 공식/Leiden의 IFR·방향 격차 G·총 판정차 D_flow·형상 변화로 완결한다. 시설 데이터가 별도로 생겼다는 이유로 자동 확대하지 않는다. 기존 XLSX의 경계별 분모 불일치와 실제 D_flow 산출 부재가 먼저 해결되어야 한다.
- **02 JTG**는 게재본을 보존한다. 기존 결과를 새 co-association 방법의 결과로 바꾸거나, 중복을 발견했다는 이유만으로 조용히 정리하지 않는다.
- **05**는 최신의 5장 구성과 제4장 4절 연결을 작업 기준으로 삼는다. 교수 원문은 5~6장 가능성을 열었으며, 향후 분장은 집필 후 판단하는 문제다. 오래된 8장 구상으로 되돌아가지 않는다.

### 실제 읽기와 이전 읽기의 재사용

기존 `antigravity-research-read-20260923/READING_HANDOFF_KO.md`는 9월 5개 대화의 공개 메시지 168개(사용자 59, assistant 109), 211,294문자를 구간별로 모두 읽고 잘린 출력은 다시 읽었다고 기록한다. 이번에는 해당 5개를 현재 DB에서 다시 추출해 **이전 JSON과 메시지 배열이 전부 동일함**을 확인했다. 이 선행 전문 읽기와 현재 사용자 발언·핵심 assistant 답변·현행 소스의 재대조를 결합했다. 새로 발견한 6월 2일 대화는 8개 메시지 전부를 읽었다. 따라서 이전 전문 읽기를 재사용한 부분을 이번에 처음부터 모두 재독한 것으로 표현하지 않는다.

SQLite는 `mode=ro`로 연결했다. 사용자 텍스트와 공개 assistant 텍스트만 추출했고, 사용자 text와 content-parts의 일치 및 해독 오류 0건을 확인했다. 내부 추론·모델 생성 메타데이터·도구 step을 메시지로 수집하거나 인용하지 않았다. 전체 step 3,863개는 도구·상태 등을 포함하므로 메시지 수가 아니다. 공개 메시지의 표기는 대화 ID + DB `idx` + 역할로 고정한다.

legacy .pb는 기존 일반 protobuf 필드 reader로 읽을 때 ValueError가 나왔다. 설치 앱의 읽기 경로 조사에서도 확인된 export/RPC decoder를 얻지 못했다. 파일이 암호화되었다고 단정하거나 비공식 복호화를 시도하지 않았다. 추후 앱이 제공하는 대화 열기/내보내기로 아래 7개 본문을 확보하면 요구사항 표를 증분 보완해야 한다. artifact는 AI가 작성한 설계·완료 보고이며 사용자 발언의 대체 근거가 아니다.

## 3. 증거 우선순위와 표기

1. 현재 요청 및 가장 최근의 명시적 사용자 교정.
2. 사용자의 직접 요청, 교수 녹취 원문.
3. 실제 현행 소스·재현 가능한 감사 JSON·파일 대조.
4. assistant 답변·brain 계획·완료 보고는 제안 또는 주장으로만 사용.
5. 오래된 기억·과거 문서는 배경. 최신 직접 결정을 덮어쓰지 않음.

`L` = Living Zone Code Review (`9b77debc-…`), `T` = 시계열 논문 피드백 반영 설계 (`02f5cac1-…`), `E` = 박사논문 형평성 평가 브레인스토밍 (`8a4dafd5-…`), `D` = 데이터구축 (`c7172d7f-…`), `J` = 6월 2일 무제 (`83833f7e-…`). `U`는 사용자, `A`는 assistant이다. 날짜가 겹치는 대화는 각 idx 순서를 우선한다.

사용자가 긴 assistant 답변을 붙인 다음 질문한 경우, 붙여넣은 “100% 검증”, “최적”, “표준”을 사용자의 독립된 사실 확인으로 승격하지 않는다. 예: T U213/U324/U340, L U505/U510/U514. 반대로 L U542의 공통폴더 통합 승인은 직전 제안의 “해상도별 합의 반복을 유지한 채 가속”이라는 조건과 함께 해석한다.
