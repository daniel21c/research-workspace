## 3. 00 공통 코어의 방법 명세

### 3.1 directed OD와 계층별 IFR

관측 통행량을 `f[o,d] ≥ 0`, 고정한 유효 OD 행집합을 Ω, partition P의 동 소속을 `z_P(o)`라 한다. 모든 통행 분자는 이동인구 가중합이며 OD 행 개수나 시설까지의 경로 개수가 아니다.

```
I_P(o,d) = 1  if O와 D 모두 유효 mapping이고 z_P(o)=z_P(d), else 0
T(S)     = Σ_{(o,d)∈Ω, o∈S} f[o,d]
N_P(S)   = Σ_{(o,d)∈Ω, o∈S} f[o,d] × I_P(o,d)
IFR_P(S) = N_P(S) / T(S)
```

- 동별: S={출발동}. 분자는 해당 동에서 소속 생활권으로 간 통행이다. `O=D`인 동 자체 완결률과 다르다.
- 생활권별: S=해당 zone의 동 집합.
- 구별: S=해당 구 동 집합, 내부 판정은 여전히 생활권별이다. 같은 구의 서로 다른 생활권으로 간 통행은 분자에 넣지 않는다.
- 서울 전체: 원량을 먼저 합하여 계산한다. 각 동/zone/구 비율의 단순 평균은 별도 기술통계로만 제공한다.
- 분모 0은 0%가 아니라 `NA + no_outflow`로 표기한다. 분자·분모는 float64 등 정밀 타입으로 합산하고 최종 표시에만 반올림한다. 현재 구/서울 집계에서 반올림된 하위 IFR을 다시 가중평균하는 경로는 원량 집계로 바꾼다.

**현재 정책과 표현을 먼저 일치시킨다.** 실제 `common_flow_loader.py`, `run_common_engine.py`, Leiden 로딩은 서울 출발·서울 도착만 남긴다. “전체 출발통행”은 이 Ω 안에서의 전체이며 다른 생활권·다른 구로의 유출은 포함하지만 서울 밖 유출은 제외된다. 함수 주석의 “서울 외 포함”은 현행 실행과 다르다. 권장 기본은 기존 서울→서울 profile을 유지하여 수정 전후를 비교하고, 서울 밖 목적지를 포함하는 정책은 별도 profile로 추가하는 것이다. 원자료 포함 범위도 확인하지 않은 채 분모를 넓히지 않는다.

LZ와 LD를 비교할 때 **동일 Ω·동일 출발동 집합**으로 T를 한 번 계산하여 공유한다. 한쪽 mapping에서 누락된 동을 조용히 제거하여 별도 T를 만들지 않는다. 제외가 필요하면 두 경계에 공통 적용하고 제외 인구/통행량을 기록한다. 외부 목적지의 무매핑과 내부 누락동의 무매핑을 구분하고, 결측값끼리 같다는 이유로 내부통행이 되지 않게 한다.

### 3.2 G와 D_flow를 동시에 계산

각 OD 행에 LZ 내부 여부 L, LD 내부 여부 D를 동시에 붙여 다음 네 통행량을 한 번에 합산한다.

| 셀 | 조건 | 의미 |
|---|---|---|
| `both` | L=1,D=1 | 두 경계에서 모두 내부 |
| `ld_only` | L=0,D=1 | LD에서만 내부 |
| `lz_only` | L=1,D=0 | LZ에서만 내부 |
| `neither` | L=0,D=0 | 두 경계에서 모두 외부 |

```
T       = both + ld_only + lz_only + neither
IFR_LZ  = (both + lz_only) / T
IFR_LD  = (both + ld_only) / T
G       = IFR_LD - IFR_LZ = (ld_only - lz_only) / T
D_flow  = (ld_only + lz_only) / T
```

출발동·구·서울별 같은 함수를 쓴다. G는 순방향 차이, D_flow는 상쇄 전 총 판정차다. `abs(G)`로 D_flow를 대체하지 않는다. 예를 들어 T=100, both=30, ld_only=20, lz_only=20, neither=30이면 G=0이지만 D_flow=.4다. 저장 결과에는 네 원량을 포함하여 독자가 식을 검산할 수 있게 한다. D_flow의 범위 0~1, `|G|≤D_flow`, IFR 차이 항등식을 검사한다.

### 3.3 원본 공식 경계와 동 재구성 경계를 분리

현재 `seoul_official_livingzone_116.gpkg`의 공식 원본과 `seoul_boundaries_all.gpkg/official_livingzone_116`의 동 재구성 경계는 동일하지 않다. 기존 감사에서 116개 모두 면적 차이가 있고 paired IoU 최솟값 .746752, 중앙값 .991728이었다. 이 차이는 코드 오류, 기초 경계 해상도, 동과 생활권의 정의 차이를 구분해 해석해야 한다.

권장 표시명은 `official_original_116`, `official_dong_reconstructed_116`, `ld_2020_<profile>`, `ld_2025_<profile>`다. 면적 단위는 투영 CRS(EPSG:5179)로 고정하고 원 CRS도 manifest에 보존한다. 지오메트리 repair를 하면 바뀐 개수·면적·원본 hash를 기록한다.

- 공식 계획의 형상을 논할 때: 원본 공식 polygon 대 LD를 주 비교로 권장한다.
- 이동 OD의 동 단위 동일조건 비교: 동 재구성 LZ 대 같은 동 기반 LD를 함께 제공한다.
- 원본 대 동 재구성은 별도의 **표현 차이/재현도** 표다. 이것을 공식 대 LD의 불일치로 읽지 않는다.
- 동 단위 OD만으로 원본 polygon 내부의 분할동 통행을 정확히 나눌 수는 없다. polygon 기반 접근성과 동 crosswalk 기반 IFR을 결합할 때 표현 차이를 명시하고, 해당 동·격자·인구 영향과 재구성 민감도를 제시한다. 원본 polygon을 사용했다는 이유만으로 이동 IFR까지 원본 경계 정밀도로 계산되었다고 말하지 않는다.

### 3.4 IoU: 기존 방식의 이름을 고치고 실제 일대일을 별도로 구현

현재 `calculate_iou`는 각 LZ별로 독립적으로 가장 큰 IoU의 LD를 고른다. LD가 여러 LZ의 파트너가 될 수 있으므로 **방향 최대중첩 매칭(다대일 허용)**이다. 기존 결과는 이 이름과 orientation을 붙여 보존한다. 1:1이라고 주장하려면 별도 assignment가 필요하다.

권장 새 일대일 정의는 각 구의 원본 A와 B 전체를 포함하는 assignment에서 교집합 면적합 `Σ|A_i∩B_π(i)|`를 최대화하고, `Σintersection / Σunion`을 보고하는 것이다. 모든 A/B를 한 번씩 포함하고 불일치 개수는 empty dummy로 채우면 `Σunion = Σarea(A)+Σarea(B)-Σintersection`이므로 교집합합 최대화와 이 비율 최대화가 일치한다. **쌍별 IoU합 최대화는 다른 목적함수**이므로 사용한다면 다른 method ID를 준다. deterministic tie-break와 unmatched 항목을 저장한다.

영교집합 처리에서 현재 `best_union=0`을 그대로 합산하는 버그를 고친다. 방향 최대중첩은 각 A에 선택한 쌍의 실제 union을 포함한다. 모든 후보와 교집합이0이어도 후보 B가 있으면 고정 tie-break로 하나를 선택하여 그 쌍의 union을 남긴다. 후보 B 자체가 없으면 unmatched A의 면적을 남긴다. 이 방향형에서 미선택 B 전체의 면적까지 더하면 지표 정의가 바뀌므로, 미선택 B는 개수·면적 coverage 진단으로만 보고한다. 일대일 방식은 모든 A/B를 한 번씩 포함하며 unmatched 항목을 dummy와 연결하여 해당 면적을 분모에 넣는다. 빈 geometry/면적0은 진단 오류 또는 NA로 표시하고 누락시켜 높은 IoU를 만들지 않는다. 정방향/역방향 다대일 결과는 다를 수 있으며 대칭적인 단일 “경계 일치도”처럼 부르지 않는다.

주 분석을 어느 지표로 할지는 연구 판단이지만, **명칭·영교집합·완전성 수정과 기존/새 지표 병렬 출력은 먼저 구현 가능**하다. 게재 JTG 수치를 새 assignment로 덮어쓰지 않는다.

### 3.5 Leiden: 합의 알고리즘 보존과 재현성을 분리

사용자는 느리더라도 각 해상도에서 반복합의를 끝낸 후 목표 개수 여부를 판단하라고 요청했다. 권장 구조는 이를 그대로 보존한다.

1. 고정 node 목록과 edge 목록을 정렬한다. 고립동도 명부에서 명시적으로 다룬다.
2. 구×연도×해상도×반복번호로 deterministic seed 목록을 만든다. `seed=None`과 실행순서 의존 난수를 제거한다.
3. 각 seed의 membership을 고정 node 순서로 정렬하여 `C[i,j]=평균(같은 군집 여부)`를 누적한다. 정수 count 후 나눗셈을 권장하며 기존 loop 대비 벡터화 행렬을 정확 대조한다.
4. 현재 방식인 `C≥tau` graph의 연결성분을 consensus partition으로 사용하는 규칙을 명시한다. 연결성분 안 모든 쌍이 tau 이상인 것은 아니다(A–B, B–C 연결만으로 A–C가 같은 성분). 지리적 인접성도 자동 보장되지 않는다. 이들을 새로운 강제 제약으로 바꾸려면 별도 방법 버전이 필요하다.
5. **모든** 해상도에서 동일한 K·tau 규칙으로 consensus 후 목표 개수·Q·IFR을 평가한다. 목표 개수를 만족한 후보의 선택 기준은 기존 `Q 우선, IFR 차순`을 보존하고 tie-break를 기록한다. 해당 표본/gu의 공식 목표 수와 총116 일치를 확인한다.
6. coarse scan과 fine scan의 모든 시도·실패·해상도·seed·후보를 기록한다. 목표 수에 못 미치면 실패로 종료하며 기존 정본을 교체하지 않는다.

현재 코드 K=200, tau=.5, gamma .01~2.50 step .01이며 `NUM_ITERATIONS_FINAL`은 선언만 있다. 대화 A515/U542의 문맥에는3000 유지가 있지만 후속 AI 보고는200~1000이다. **권장 기본은 기존 산출물 profile을 보존하고, 문서 재현용 K=3000 profile과 빠른 점검용 K=200 profile을 이름으로 분리하는 것**이다. 최종 논문 반복 수를 코드 편의를 위해 몰래 낮추지 않는다. 먼저 작은 합성/한 구 fixture로 파이프라인을 검증하고, 그 뒤 필요한 K·seed batch의 안정성/비용을 기록해 본 실험 사양을 결정한다.

라벨번호 불변성, 같은 seed 재실행, 서로 다른 seed의 안정성은 다른 검증이다. 고정 입력·고정 seed에서는 membership 정규화 hash/ARI가 같아야 한다. 다른 seed에서는 ARI·VI·목표 개수 충족률·Q/IFR 분포를 실제 측정한다. 한 구 gamma=1에서 ARI=1이었다고 모든 구·해상도에서 ARI=1을 보장하지 않는다. 논문 주장을 위한 전 구 검증은 계약 수정 후 별도 분석 단계다.

현재 Leiden graph 생성은 역방향을 붙여 양방향 행을 만든 뒤 undirected igraph에 모두 넣고 self-loop를 제거한다. 공통 Q 엔진은 NetworkX Graph로 만들며 self-loop 처리도 다르다. 이것이 모든 결과를 틀리게 만든다고 아직 단정하지 않는다. 다만 원 JTG의 loop/중복 edge convention과 맞춘 **생성용 graph와 평가용 graph**를 각각 정의하고 소형 hand graph로 edge weight·총량·Q를 대조해야 한다. IFR의 원 directed flow는 이 변환에 재사용하지 않는다. 구 내부 Q로 후보를 고르는 것과 서울 전체 graph에서 경계 간 Q를 비교하는 것도 구분한다.

### 4.3 출력 지표와 해석

- 효율: 고정 전체인구 분모의 coverage, 총/인구가중 이동부담, baseline 대비 개선. 시간단위·미도달 처리·cap을 명시한다.

- 공간단위별 최소 coverage·분산은 보조표다. 큰 단위로 합칠수록 격차가 숨겨지는 MAUP 영향을 고정 미시단위 지표와 함께 보여준다. Theil 분해는 양수/0 처리와 중첩관계가 적합한 지표에서만 별도 탐색한다.

초기 검증은 작은 완전탐색 가능한 합성 도시로 최적해·예산·형평 지표를 확인한다. 다음 한 구에서 최소3개 예산 수준과 여러 후보/가상수요 seed를 비교한 뒤 서울 확장 여부를 판단한다. 실제 고정자료의 반복 solver 실행을 새로운 독립 표본처럼 세지 않는다. heuristic이면 동일 연산예산·종료조건과 최적성 한계/상계 비교를 기록한다. 결과가 생활권 우월을 지지하지 않아도 그대로 보고한다.

### 6.2 집계 계약

각 지표는 origin-level 값과 유효 인구 분모를 함께 보유한다. Coverage는 고정 전체인구 분모, 조건부 거리/공동입지 MAI는 해당 유효/covered 인구 분모를 사용한다. 기존 v4 inverse-distance는 생성식상 전체인구 분모지만, 그 전체가 실제 모든 origin을 포함하는지 확인해야 한다. v4는 OD에 존재하는 origin으로 base를 구성하고 taxonomy별 `pop_total`의 첫 값을 공통 분모로 쓰므로, 시설별 도달 후보 누락이 인구분모 차이를 만들지 않는지 검증한다.

상위 구로 올릴 때는 `Σ지표분자/Σ해당분모`로 집계한다. 조건부 지표를 전체 `pop_total`로 가중평균하면 다른 수치가 된다. 모든 유형의 분모가 같은지를 확인하지 않고 pivot에서 첫 pop_total을 가져오지 않는다. 시설유형별 평균은 동일한 종류 목록·명시된 가중치로 계산한다. 일부 유형이 NA이면 skipna로 조용히 평균의 의미를 바꾸지 말고 유효 유형 수·제외 기준을 남긴다.

동/생활권/구는 **관측 단위**, LZ/LD는 **내부 여부를 정하는 경계**, 접근 가능한 거리/시간은 **서비스 범위**다. 이 세 축을 별도 열로 표시한다. 기존 N25 회귀를 N423 또는 N116으로 늘리는 것은 독립적인 새 모형 설계다.

### 6.3 기본 모형과 진단

사용자 L U90에 따라 기본식은 다음으로 복구한다. 종속변수를 MAI로 바꾸는 GUIDE 문구를 고친다.

```
LZ_IFR_g = α + β1 Access_LZ_g + β2 Coverage_LZ_g + ε_g
LD_IFR_g = α + β1 Access_LD_g + β2 Coverage_LD_g + ε_g
G_g      = α + β1(Access_LD_g-Access_LZ_g)
             + β2(Coverage_LD_g-Coverage_LZ_g) + ε_g
```

`Access`에 어떤 정의를 넣었는지 식과 표 제목에 표시한다. 기존의 잘못 명명된 역거리 MAI로 재현하는 결과와 조건부 공동입지식으로 새 계산하는 결과는 다른 model ID다. IFR은 새로운 동일 OD 계약의 결과로 연결하되, 기존 IFR 입력으로 재현한 값도 차이표에 남긴다. 신규4종 접근성에 기존IFR을 무조건 붙이지 않는다. 경계 표현·기간·관측 모집단의 일치 확인이 먼저다.

권장 baseline은 기존과 같이25개 구·설명변수2개·상수항(잔차 자유도22)다. LZ/LD/Gap 세 모형은 같은25개 구를 재사용하며75개 독립 관측치가 아니다. 구 코드 one-to-one join, 완전관측 표본·탈락사유, 변수분포·분모·상관을 먼저 출력한다. 현재 코드가 controls 파일을 읽더라도 X에는 넣지 않는다는 점도 바로잡아 실제 투입식을 자동 출력한다.

검증 출력은 일반 OLS 재현값 + 소표본을 고려한 HC3 표준오차/구간, VIF, leverage/Cook's D, leave-one-gu-out 계수 범위, 잔차 지도 및 Moran's I를 권장한다. N=25에서 구별 cluster SE는 관측치당 cluster 하나라 기존 동 N423의 구 FE/cluster 처방을 그대로 가져오지 않는다. Moran 가중행렬은 구 polygon Queen을 기본으로 하고 island 처리·row-standardization·permutation seed/횟수를 기록한다. kNN은 사전 정한 민감도다. 공간의존이 확인되면 연관성 해석을 제한하고 적합한 후속 모형을 판단한다. 자동으로 SLM/SEM을 대량 실행해 유의한 결과를 고르지 않는다.

면적/compactness 등 소수 통제변수는 이론·측정단위와 함께 사전 지정한다. 구 단위 모형에서 zone compactness를 어떤 분모로 집계할지도 명시한다. 현재 주석의 면적·인구밀도와 GUIDE의 통제변수 설명을 실제식에 맞춘다. 소표본에서 모든 후보를 넣거나 R² 개선만으로 최종식을 정하지 않는다. 이 단계의 결과는 인과효과가 아니라 조건부 연관성이다.

## 10. 실행 순서와 검증 통과 기준

아래는 구현 후의 순서다. 대규모 원자료 실행 전에 작은 반례로 계약을 확인하고, 하나라도 실패하면 다음의 비용 큰 분석·정본 승격을 하지 않는다. 문서 정정과 예시 분리는 연구선택을 기다리지 않고 진행할 수 있다.

| 순서 | 입력 → 작업 → 출력 | 통과 기준 |
|---|---|---|
| S0 보존·사양 | 기존감사·현재hash·사용자근거 → profile/지표사전/수정범위 → 기준manifest | 기존변경 보존;423/424/422·8/6/4 혼용 없음;이번실행범위명시 |
| S1 계산·안전 수리 | 합성OD/geometry/mapping → core수정·실패주입 → 단위검증표 | V1~V6 전부통과, 기존정본hash불변 |
| S2 기존매핑 평가 | 현재423 mapping·동일OD → IFR/4셀/두IoU/graph평가 → 새core run | 구25/동423/zone116 확인;원량/분모일치;기존차이수식·방법으로설명 |
| S3 Leiden 시험 | 작은graph→한구→전구 후보, 고정seed/profile → 합의·scan → 새mapping/provenance | target/완전성/동일seed재현통과;다른seed안정성은측정치로보고 |
| S4 KPA | 통과core·과거표 → 분모원인대조·새진단 → 변화/불일치표 | V9;과거차이원인미해결이면기존수치인용제한 명시 |

S4는 기존mapping 기반 S2가 통과하면 시작할 수 있으며 S3의 전구 재추정을 무조건 기다릴 필요가 없다. AG 지표사전과01 실험설계도 core의 대규모 실행과 독립적으로 진행 가능하다. 새본실험의 방법선택은 결과에 영향을 주는 소수 항목만 구체안과 함께 결정하고, 사소한 경로/스키마 수리를 매번 승인대기로 만들지 않는다.
